# Sound Link v1 协议草案

> 这是完整产品协议草案，不是当前线协议。0.4.10 实际使用 pairing-v1.md、discovery-v1.md、observation-v1.md 和 handoff-v1.md；普通事务期限已为 5 秒。本文的 lease/exit/release 消息和 15 秒预算不能当作现有实现，退出归还未落地。


状态：后续协调协议草案，2026-10-14；0.1.0 的实际安装/配对接口以 [pairing-v1.md](pairing-v1.md) 为准，本文的事件流、目标和交接接口尚未实现。协议描述认证后的局域网消息，以及配对/GATT 引导字段，不包含音频流。任何示例值均为占位值，不能作为真实凭据。

## 身份与版本

- `device_id`：安装身份，不随 IP、系统名称或 App 更新变化；关联到长期公钥。
- `pairing_id`：双方的持久授权记录，可撤销；不由广告名或蓝牙地址推导。
- `process_id`：每次进程启动生成的新随机标识，用于诊断，不作安全身份。
- `epoch`：Mac 创建的一次协调会话。重连、恢复、目标更改和服务重启都生成新值。
- `target_id / target_revision`：耳机逻辑身份和单调配置版本；端侧原生地址保存在目标映射中。
- `protocol_major / minor`：major 不兼容拒绝控制；minor 通过能力协商，未知消息不得默认执行。

首期只允许一对活动 Mac/Android 和一个耳机目标。多电脑争抢与账号同步不在 v1 内。

## 引导对象

配对码使用 App 内识别的 `soundlink://pair` 结构化负载，包含 `v`、Mac 身份、公钥指纹、邀请 ID/secret、过期时间、实例服务 UUID 和候选 endpoints；限制总大小和地址数量。Mac 的到期判断有最终权威，不能依赖手机时钟决定邀请有效。二维码不能直接授予耳机动作权限，仍需 Mac 确认、系统授权和会话建立。

GATT `EndpointDescriptor` 包含 `device_id`、`endpoint_revision`、`protocol_versions`、候选 `{host, port, transport}`、`available`、身份指纹与认证扩展。初期固定为局域网 TLS，不接受来自描述的任意 scheme、外部下载 URL 或 shell 参数。响应分片、最大长度和读偏移必须严格检查。签名及挑战应答的编码格式在冻结时给出正反例，不使用浮点 JSON 的隐含规范化。

## 局域网入口

| 入口 | 权限 | 用途 |
|---|---|---|
| POST /v1/pair | 被扫码固定身份的 TLS + 有效邀请 | 绑定、人工确认和幂等结果查询流程 |
| POST /v1/session | 已配对设备密钥证明 | 能力协商、新 epoch、目标和状态基线 |
| GET /v1/events | 当前认证会话 | 有界 NDJSON 下行事件流 |
| POST /v1/messages | 当前认证会话 | 状态、挑战回应、播放候选和事务结果 |
| GET /v1/target | 已配对身份 | 查询目标与版本，用于断线恢复 |
| POST /v1/target | 已配对身份 + expected revision | 持久更换目标，结束旧 epoch |
| POST /v1/unpair | 已配对身份或本机用户 UI | 撤销配对并停止旧控制 |

具体密钥证明和 session token 的颁发/轮换必须在实现时完成安全测试。不能将一个二维码长期 secret 当作所有请求共用的永久 Bearer token。单连接读取限速、总帧大小暂定 16 KiB，限制嵌套深度和队列长度；慢消费者丢弃可重建状态并重新握手，不无限积压控制消息。

## 消息信封

```json
{
  "protocol_major": 1,
  "protocol_minor": 0,
  "type": "state.snapshot",
  "message_id": "random-message-id",
  "pairing_id": "paired-device-record",
  "epoch": "current-coordination-session",
  "sender_id": "paired-device-id",
  "sequence": 12,
  "target_id": "selected-headphones",
  "target_revision": 3,
  "payload": {}
}
```

接收端验证认证身份、类型白名单、epoch、目标版本、序号和消息大小后才交给状态机。重复 ID 返回已知结果，不重复动作；旧 epoch/target 只能用于诊断，不能改变当前归属。关键事务幂等结果需要跨短暂重连持久保存；进程重建后任何未完成动作先查询状态，不重放连接。

## 时效与租约

墙上时钟只用于展示。各端以包含休眠时间的单调时钟检查动作期限，禁止直接比较两端 timestamp。

建立会话和续约使用新随机 challenge/response，response 必须匹配当前待处理 challenge，且往返耗时不超过协商上限。期限从本地 challenge 发出时刻计算，不能从积压 response 到达时重新加完整 TTL。暂定 TTL 10 秒、最大续约 RTT 3 秒；正常双向状态与确认可承载 challenge。单向流有数据不代表双向租约有效。

检测到超过 TTL 的执行空白、网络重建或未知计时状态时，废弃积压帧和旧会话，重新认证/建立基线。每个硬件动作前再次检查本地期限。过期后的“最后一次续约”不能复活旧 epoch。

## 消息类型

| 类型 | 内容与作用 |
|---|---|
| session.ready | 双方能力、epoch、目标版本、新基线完成 |
| lease.challenge / lease.response | 新鲜性确认与租约；挑战绑定会话与发送身份 |
| state.snapshot | 耳机 profile、音频路由、Mac 可用性、保护状态；字段明确 unknown |
| playback.candidate | 基线后的新事件、类别/置信度、事件 ID；不是连接命令 |
| handoff.prepare / ready | 目标确认可接收与本地短期许可；未 ready 不释放来源 |
| handoff.release / released | 来源执行一次释放并报告实际结果 |
| handoff.connect / result | 目标执行一次连接、报告 profile/路由或失败 |
| session.exiting / exit.ready | 终止普通事务，建立一次性短退出许可 |
| exit.return / exit.result | 已确认来源释放后的归还，绑定旧 epoch 与目标版本 |
| session.stopped | 撤销监听和协调；丢失时仍靠本地租约到期 |
| error | 可诊断错误和是否允许重新握手，不指示无限自动重试 |

`handoff.*` 统一带 `transaction_id`，每个动作带 `command_id`。接收端在 ready 时建立本地事务截止时间；后续 release/connect 只能消费该许可，网络迟到不能增加时限。普通事务总期限暂定 15 秒，且不得越过当前有效协调权限。

退出事务与普通事务分开：手机先在有效旧会话中确认 `exit.ready`，创建不超过 3 秒的本地“可发起归还”窗口；`exit.return` 只有在该窗口内、来源已确认释放、目标版本未变时可消费一次。连接发出后允许最多 15 秒只观察结果，不再发新连接；不要求 Mac 持续运行。没有 ready 或命令丢失不补做无限归还。

## 状态字段与错误

耳机状态至少有 `unknown / disconnected / connecting / connected / disconnecting`，音频路由有 `unknown / headphones / speaker / other`。蓝牙连接、profile 与输出路由独立上报，不能用一个布尔值替代全部状态。保护状态未知且可能处于通话等冲突时，不进行普通抢占。

错误至少区分 `INVITE_EXPIRED`、`IDENTITY_MISMATCH`、`PAIRING_REVOKED`、`NETWORK_UNREACHABLE`、`PERMISSION_DENIED`、`BACKGROUND_RESTRICTED`、`PROTOCOL_MISMATCH`、`STALE_EPOCH`、`LEASE_EXPIRED`、`TARGET_MISMATCH`、`TARGET_NOT_PAIRED`、`PROFILE_UNAVAILABLE` 和 `HANDOFF_TIMEOUT`。

目标更换需携带 `request_id` 与 `expected_target_revision`；重复提交返回同一结果，冲突返回当前版本，中断后先查目标。双方已确认同一新版本和授权才恢复。失败不回滚用户系统蓝牙配对、不暗中切回旧目标。
