# Sound Link 设备发现与配对

本方案将安装、身份绑定、在场发现和实时连接分开。目标是通用 APK 在首次扫码后长期识别同一台电脑；更换 Wi-Fi、IP 或重启不要求重新安装。

## 下载二维码与配对二维码

| 二维码 | 内容与入口 | 生命周期 |
|---|---|---|
| 下载 APK | Mac 展示云端 HTTPS 下载页；手机相机或浏览器打开 | 固定下载入口，不含配对凭据 |
| 配对此 Mac | Android App 内扫码，获得电脑身份、公钥指纹、发现提示和一次性邀请 | 暂定 5 分钟，一次使用，可刷新或取消 |

默认开发构建不配置下载站点或在线更新。分别安装配套开发包后扫码配对。Mac 不内置 APK，也不提供局域网下载页；配对在局域网 TLS 端口进行。

首次安装后重新扫描配对码，不依赖浏览器把安装前的邀请自动传入 APK；过期只刷新邀请，不更换设备身份。

## 首次建立信任

1. Mac 首次运行在钥匙串创建长期设备身份与密钥，显示设备名称；用户打开“连接手机”时生成随机一次性邀请。
2. Android 扫码读取协议版本、`device_id`、公钥指纹、发现 UUID、候选局域网地址以及邀请 ID 和随机 secret。至少 128 位随机强度；二维码不含长期私钥或全局通用密钥。
3. App 请求本步骤所需权限，用二维码地址尝试连接；失败时通过 BLE 读取新地址。地址和广告名称只用于定位，不能证明身份。
4. TLS 握手将服务端身份绑定到二维码公钥指纹，不能使用“信任全部证书”。邀请在受认证的加密通道内提交。Mac 显示申请手机的名称，用户确认本次绑定。
5. Android 建立本机密钥；双方记录配对身份及授权范围，邀请原子消费，建立可撤销的长期配对记录。失败重试必须有请求 ID，断线后可用新密钥证明身份并查询结果，不能重复创建配对。
6. Android 分别请求 Mac 在场观察关联和目标耳机控制关联。普通系统蓝牙配对、App 身份配对和伴生授权是三种不同状态。
7. 两端同步耳机目标，建立全新协调会话，读现状后进入等待或协调。

0.1.0 已实现步骤 1–5 的身份与配对；准确字段、签名和证书校验见 [已实现协议](../packages/protocol/pairing-v1.md)。步骤 6–7 及 BLE/GATT 自动找回尚未实现。本版用扫码地址建立连接，配对后可扫码更新同一身份的地址。

## BLE 在场与地址发现

Mac 使用 CoreBluetooth 广播稳定的实例服务 UUID 和短名称 `SL-四位数字`。UUID 随设备安装身份生成并持久化，不随升级、IP 或会话变化；名称可以重复，不作为身份依据。首期每台 Mac 一组实例 UUID，配对码提供过滤值，避免依赖全局同名广告。系统可能合并其他 App 广播、截短或缓存名称，界面不能以名称不同认定不是该 Mac。

Mac 公开广播入口只支持本地名称和服务 UUID，所以不将 IP 硬塞进名称或动态 UUID。发现后 Android 建立短期 GATT 连接，读取动态连接描述。0.2.0 已实现紧凑签名描述、随机挑战及动态读取，协议单测通过；**真实 GATT 路径仍待本轮实机确认**。准确字段见 [discovery-v1](../packages/protocol/discovery-v1.md)，不能因旧版已广播一个静态只读字段就算地址发现成功。[CoreBluetooth 广播](https://developer.apple.com/documentation/corebluetooth/cbperipheralmanager/startadvertising(_:))、[动态特征值读取](https://developer.apple.com/documentation/corebluetooth/cbperipheralmanagerdelegate/peripheralmanager(_:didreceiveread:))。

连接描述包含协议版本、设备 ID、地址版本、候选 IP/端口、身份指纹和可用状态；不包含配对 secret 或持久令牌。已配对端可使用挑战应答及身份签名验证描述的新鲜性；最终控制连接仍必须验证已保存的身份。限制字段大小、GATT 分片、读超时与尝试次数，读取完成关闭连接。

IP 变化时更新 GATT 描述和可选 Bonjour/NSD 发布，不更改设备身份。仅提供当前可达局域网候选地址，避免把回环、虚拟机或不可用 VPN 接口排在前面；对 IPv4/IPv6 分别验证。收到地址后连接失败属于“网络不可达”，不是蓝牙配对失效。

## 已配对设备的恢复

优先尝试近期有效地址；网络切换或连续失败后重新解析 Bonjour/NSD 或通过 BLE 读取 GATT。二者是地址发现途径，不能绕过身份校验。不要求 mDNS 在所有路由器工作，也不无限轮询扫描。连接重试采用有上限的退避和事件触发恢复；局域网连通和 BLE 可见分别显示。

Android 的伴生在场服务及带过滤条件的 BLE PendingIntent 是唤醒候选路径。CDM 对随机蓝牙地址有限制；Mac 地址变化、进程被清理和系统重新绑定时都要实测扫描恢复。收到广播只进入验证状态，不能立即注册有效协调或连接耳机。[Android 后台 BLE](https://developer.android.com/develop/connectivity/bluetooth/ble/background)。

## 信任和会话的有效期

| 对象 | 约束 |
|---|---|
| 设备身份、配对记录 | 持久化，可由用户撤销；不因四小时截止强制重新扫码 |
| 配对邀请 | 短期、一次性；过期需新邀请 |
| 传输认证 | 每次连接验证双方身份；短期授权在可信连接内续期 |
| 协调会话 | 每次恢复生成新 epoch，状态过期即无动作权限 |
| 单条控制命令 | 有事务 ID、目标版本和短期限；过期或重复不能再次执行 |

Mac 私钥进入 Keychain，Android 私钥进入 Keystore；配对删除后撤销控制与相关唤醒注册。密钥变更无旧身份有效证明时必须重新扫码，不能根据同名 Mac 自动信任新密钥。服务端 TLS 身份绑定稳定设备身份，IP 仅作路由；主机名/SAN 与 pinning 的具体信任策略必须一起实现，不能简单关闭 hostname verification。

## 产品化阻塞项

GATT 地址发现实测、跨 IP 的身份验证、厂商锁屏唤醒、API 37 局域网授权均需验收。会话过期、地址变更和扫描受限分别诊断；更换通信协议不会自动解决系统后台限制。
