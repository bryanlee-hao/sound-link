# 锁屏诊断（0.3.1）

目标：在不增加唤醒锁、定时唤醒或更改省电设置的前提下，记录每次心跳间断与恢复的可验证证据。本次是诊断增强，不是后台恢复修复。

## 测试与取证

1. 两端升级 0.3.1，确认正常心跳。手机“锁屏诊断”点“标记测试开始”，记录是否划掉 App、供电/USB、调试开关、网络和屏幕条件。
2. 保持 Mac 正常运行；手机锁屏，按测试计划决定是否划掉 App。不要为读取日志临时亮屏或连接 ADB，否则应记录该干预时间。
3. Mac 的“锁屏诊断”展示随正常心跳收到的最近手机摘要。失联时标为历史，不凭历史摘要宣称当前状态。
4. 测试结束后解锁手机，点“标记测试结束”及“导出完整诊断日志”。系统分享页由用户选择保存或发送目标；未选择前不会向第三方发送。
5. Mac “打开诊断日志文件夹”提供手机摘要与 Mac 自身暂停、休眠、退出、心跳过期事件。完整手机 JSONL 与这些摘要互相对照。

## 日志内容

每条手机 JSONL 含版本、墙钟毫秒、elapsedRealtime、uptimeMillis、boot count、PID、进程启动 UUID、线程、序号、测试 UUID、事件类型和结构化数据。

| 证据 | 可判断的事 | 不能据此判断的事 |
|---|---|---|
| 新的进程 UUID + PID/boot/version | 确认进程重建，区分手机重启/版本升级背景 | 单凭重建不能确定系统杀进程原因 |
| 匹配前一 PID 和时间窗口的 ApplicationExitInfo | Android 报告的崩溃、ANR、内存回收、用户请求、升级等退出原因 | 缺失记录不代表没有终止；SIGKILL 不等于已知谁杀的 |
| service_create/start_intent/destroy/task_removed | 服务实例生命周期、重复启动入口、划掉任务回调 | service_destroy 不是整个进程退出；task_removed 不代表服务已被杀 |
| elapsed 差 − uptime 差 | 同一进程两次执行之间，设备经历的深睡时长近似值 | 不能用它证明 App 被冻结 |
| uptime 差超过任务预期间隔 | CPU 醒着时任务迟到，可能调度、冻结或线程阻塞 | 普通应用不能据此确定唯一原因 |
| 主线程脉冲 + 心跳线程 tick + 请求阶段 | 对照哪个线程继续运行、哪个任务/请求阻塞 | 主线程与工作线程同时迟到仍不等于系统冻结的直接证据 |
| request_phase / request_success / request_failure | OPEN、CONNECT_TLS、WRITE_BODY、READ_HEADERS、READ_BODY、VERIFY_RESPONSE，耗时及异常类型链 | CONNECT_TLS 合并 TCP/TLS，不能假装已经细分到底层握手包 |
| 心跳失败 + retry_in_ms | 程序主动退避与网络/调度间断的差异 | 在线计数增长不是进程启动次数 |
| 屏幕、锁定、idle、省电、后台限制、网络回调 | 事件发生时可读的系统状态 | Wi-Fi 或网络 validated 不保证 Mac 的局域网服务可达 |
| BLE first-match/match-lost、伴生事件、wake_entry | 恢复入口是否被触发/接受/去重 | 广播回调不证明此前进程已死 |

主线程采用 Handler 每 5 秒的非唤醒检测；心跳线程按原约 3 秒 fixed-delay 流程测量“上次任务完成到本次开始”的间隔，因此不会把上次 HTTP 执行时间直接冒充线程调度间断。主线程正常脉冲约 30 秒记一次；异常间隔及时记录。睡眠期间无法运行日志，证据是在恢复后计算得到。

## 保存与边界

手机私有目录 `files/diagnostics/` 保存最多 4 个约 1 MiB JSONL 文件，异步串行写入，队列有上限。队列丢弃与写入错误计数在摘要显示；它们是当前进程计数。突然终止可能丢失尚未落盘的末尾事件，系统退出记录用于补充。升级保留日志，不因新测试标记删除历史。

导出 ZIP 包含 `summary.json`、说明与当前保留的 JSONL；文件通过非导出的只读 ContentProvider 临时授权系统分享目标。日志不记录 HTTP body、Authorization、配对邀请码、证书或密钥、SSID、声音及媒体内容；记录请求路径、状态码、受限的服务错误码和异常类型，不复制异常完整消息/堆栈。

手机摘要随现有认证心跳上报，没有额外网络轮询。Mac 保存到 `~/Library/Application Support/Sound Link/Diagnostics/`，最多两个约 2 MiB 文件；只含摘要，不替代完整手机日志。诊断本身有少量 CPU/I/O 开销，不能宣称对省电行为零影响。

## 0.3.2 播放事件与对端收到测试

保持原约 3 秒 HTTPS 轮询、恢复入口与观察暂停规则；本版只加测量，不加唤醒锁、不维持 GATT 长连接、不主动唤醒手机。

新增 `phone_playback_changed`（回调/轮询/音频 profile 来源、匿名播放状态、事件序号、屏幕/锁定/电源状态）、`observation_start/stop`。最近一次播放状态独立留在诊断摘要中，避免被其他八条事件覆盖；`summaryElapsedMs - latestPlayback.elapsed_ms` 可估算同一进程内事件观察到准备上报的间隔。它不包含播放开始到音频观察回调到达的延迟，不能冒充用户按键到达延迟。

Mac 将自身观察变化记为 `mac_playback_changed`，手机样本变化记为 `phone_observation_received`。Mac 状态变化附随机诊断标识，通过下一次心跳响应交给手机；手机成功校验后记录 `mac_state_received`，下一次心跳回传确认。Mac 的 `mac_state_receipt_confirmed.roundtrip_upper_bound_ms` 使用同一 Mac 单调时钟，包含回传等待，表示送达耗时上界，不能称为精确单向延迟。标识不授予控制权；`active_wake_sent=false` 明确表示没有主动唤醒动作。Mac 下一次状态变化会替换当前标识；早于确认的旧标识仍可从完整手机日志/原始摘要追查，但不混算成当前状态确认。

测试准备：升级两端，检查正常心跳和目标映射；关闭无线调试、拔 USB、保留 Wi-Fi 与蓝牙，记录当前省电设置。用已加载的音乐，先播放再暂停；手机处于后台，暂不叠加划掉任务。每组先做 1 次基线，后续至少重复 3 次，再独立测试划掉 App。

### A：手机全程息屏起播

耳机先连接手机，Mac 暂停音频。在手机标记测试开始后锁屏，静置至少 2 分钟，待 Mac 已观察到心跳过期/深睡间隔，再通过耳机物理按键恢复手机音乐，保持播放至少 30 秒。不要触摸手机或用锁屏播放器按钮；用户从 Mac 回复实际按键时间及是否听到声音。若通知造成屏幕亮起，单独标为受干扰样本。

观察：用户起播时间（手工时间只作近似）→ 本机 audio_callback/poll 与状态 → Mac 收到新样本 → 心跳持续性。耳机已在手机，本组验收上报能力，不要求出现切换候选。原逻辑心跳超过 10 秒会暂停观察，重连后重新建立边沿基线，因此“收到 active 状态”与“捕获新播放边沿”必须分开判定；不能为了测试通过而重放已有播放。

### B：Mac 起播，手机全程息屏

手机音乐暂停、耳机继续连接手机；两端先空闲，手机重新息屏静置至少 2 分钟，等待新一次心跳过期后，在 Mac 开始一段本地音乐/视频，保持播放至少 30 秒。记录 Mac 观察时刻、手机收到诊断标识及下一次回传确认；将手机屏幕、进程/调度和恢复入口对齐。

当前链路只提供轮询响应，没有 Mac → 手机主动推送，因此这轮测“多久能被手机读到”，不能作为主动唤醒方案的成功证明。若只在手机自然醒来时送达或超过 5 秒，实时性预检失败；5 秒为本轮宽松测试阈值，非正式体验承诺。A/B 都不能用在线指示变化替代对端确实收到状态。若要求定量判断临界值，用原始时间/回执界限，人工按键报时不足时保留不确定。

后续候选：伴生授权和 connectedDevice 前台服务维持必要生命周期；在双端协调会话内保持 BLE GATT 通知订阅，Mac 输出事件用带身份校验/序号/期限的通知触发处理；手机播放回调触发及时上报，短时 partial wake lock 仅保护已触发事务处理。是否能在该 ROM 深睡中及时回调，需与本次轮询基线做实机对照，不能事先保证。长期唤醒锁、省电豁免可作单独对照，不直接当作默认产品方案；单独唤醒锁不能解决所有 Doze 网络限制。
