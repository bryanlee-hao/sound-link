# Sound Link 产品目标

设计基线：2026-10-14；流转规则更新：2026-10-15。当前行为基线为 0.4.10。未实现目标与暂缓项单独标注；参数见[流转规则](coordination.md)，实机证据见[验证记录](validation.md)。

## 交付与首次使用

用户运行可独立安装的 Mac App 和 Android App，无需独立 server。开发安装步骤见仓库 README。安装后的 Android App 扫描 Mac 配对二维码，建立持久信任，再引导完成附近设备、局域网、通知和伴生设备授权。扫码不能替代 Android 系统授权。

下载和配对是两个独立动作。下载二维码用于获取所有用户通用的正式 APK，不带控制权限；配对二维码用于绑定眼前这台 Mac，短期有效、一次使用。安装 APK 不应自动绑定生成下载码的电脑。具体流程见[设备发现与配对](discovery-and-pairing.md)。

用户在两端系统蓝牙中配对同一副耳机，在 Sound Link 中选择目标。显示系统耳机名称，地址只作区分同名设备的辅助信息；用户可以更换目标、解除电脑配对、暂停协调。新目标同步确认前不生效。第一次连接耳机仍由系统或用户完成。

## 核心体验

产品价值是日常自动交接，一键切换仅作为诊断或失败恢复入口，不作为核心功能完成标准。

| 条件 | 必须做到 |
|---|---|
| Mac 参与、有有效耳机使用证据 | 新合格媒体播放端优先接管，即使旧端仍播放音乐；不等待旧端先暂停 |
| 两端都明确未连接耳机 | 不因播放而连接耳机 |
| 手机通信中断、状态过期 | Mac 可凭仍有效的使用会话单次接管，无固定时间到期；失败后阻止后续失联尝试，直到新连接确认。手机也可在已有使用会话下独立接管，失败锁定，详见流转规则 |
| Mac 合盖、休眠、关机或主动退出 | 当前取消事务、清空本地使用会话并停止协调；主动归还尚未实现，后续方案见下文 |
| Mac 意外失联 | 手机自行让旧会话失效，不无限等待或重连耳机 |
| Mac 重新加入 | 读取新基线，等待新的播放事件，不抢占已有播放 |
| 用户停止协调或撤销授权 | 停止相应监听与动作，不靠自动恢复覆盖用户选择 |

“任一端已连接”是耳机正在使用的产品约定；“两端均断开”按不需干预处理。二者不是佩戴、入盒或盒盖检测。主动选择外放的专门识别与持久记忆暂缓，保持当前实现：路由变化重建起播基线，之后新起播仍按普通规则判断。不承诺完整识别用户外放意图。

接管成功后尽力暂停旧端，暂停不可用、失败或过期均不回滚交接；持续旧播放不能反向抢回。迟到暂停不得影响用户新启动的播放。

保留当前起播规则：Mac 新输出立即进入判断，不按播放器名单或持续时长过滤，因此通知、提示音也可能触发；Android 仍按媒体/游戏用途筛选。两端以现有输入/通信/未知用途信号保护通话和会议，不承诺完整识别全部场景；失联时用户接受无法获知远端新通话的限制。交接失败不能造成循环争抢、遗留静音或持续改变音量。不得仅因为某端一直有声音，就不断请求连接。

## 电脑退出后的边界

当前实现：Mac 正常睡眠/暂停会停止参与协调，退出 App 会停止服务；没有主动归还协议。手机收到 MAC_UNAVAILABLE 或连续失败超过约 75 秒时暂停网络轮询；有授权且有使用会话/失败锁时保留本地观察，否则结束服务。系统冻结会推迟实际清理。关闭 Mac 窗口不等于退出 App。

防重复连接是核心约束。0.4.10 将通信重试与本地新起播处理分离：Mac 失联后，手机只在有使用会话且出现新的媒体起播时尝试一次，连接及路由共 5 秒，失败恢复声音并锁定；新连接确认才能解锁。不会仅因失联自动归还耳机。

收到明确正常退出消息后的有限归还也未实现；断网本身无法区分 Mac 睡眠与仍在使用，因此未知退出不能自动归还。用户明确暂停/撤权仍停止自动动作，不被恢复覆盖。

## 支持范围与分发

首期一个 Mac、一个 Android 手机、一副目标耳机，局域网可互通且 Bluetooth 可用。不要求同一 SSID，但同 Wi-Fi 也不保证互通。无云端音频转发、无远程公网控制；音频直接走系统蓝牙。

Android 首期以 API 37 的公开连接能力为前提；旧系统不偷偷降级到隐藏 API 或调试注入。Mac 支持系统版本及 CPU 架构由干净机器打包测试确定。Windows 是后续平台，其他耳机必须逐型号验证。

分发不等于免授权：macOS 蓝牙/局域网提示、Android 安装来源许可、相机扫码权限和系统伴生确认仍需用户操作。产品引导只展示本步骤需要的权限，拒绝后解释受影响的功能。

## 界面必须区分的状态

- 已配对电脑、发现附近广播、BLE 信息读取成功、可信局域网连通、双向心跳有效。
- 耳机已在系统配对、已授权伴生控制、当前连接哪一端、音频路由是否确认。
- 自动协调、等待首次耳机连接、交接中、手机单设备、后台受限、需用户处理。

主界面显示耳机名称、两端连接状态、当前协调状态和可执行的下一步。心跳计数、广播信号、协议错误放在诊断页；过期状态显示“未知”，不沿用绿色在线状态。
