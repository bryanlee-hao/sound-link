# Sound Link 界面（0.6.12）

## 页面与状态

Mac 使用 AppKit，Android 使用 Kotlin + Jetpack Compose Material 3。浅灰背景、独立圆角面板、系统字体和蓝色状态强调，跟随系统明暗外观。

- 首页：耳机名称、两端蓝牙连接状态、本机自动切换开关、已配对设备。
- 未配对：展示 Mac／耳机／Android 连接示意、配对入口和三条功能亮点（没有 Multipoint 也能流转、AirPods × Android × Mac、后台随播放切换）。Mac 下载码和配对码分开；有效扫码请求验证签名和邀请后直接配对，不再弹出二次确认；邀请过期自动生成新码。
- 设置：两端统一“设备与连接 / 通用 / 帮助与关于”分组和顺序。Mac 图标列固定 18 pt、与文本间距 12 pt，语言选择靠左；卡片采用明确的明暗背景与细边界。Android 顶部返回、设置使用有背景的圆形图标按钮，保留无障碍标签。
- 诊断：导出日志、恢复声音、高级诊断。心跳、地址、协议状态和原始判断记录只在高级诊断显示。

首页的“已连接”表示当前目标耳机的连接证据，不宣称佩戴、播放或音频路由已经确认。过期、不同目标版本、重启前的样本不能显示为已连接；两端均连接时明确显示两端连接。自动切换暂停与连接暂停是独立状态。

新配对成功后两端自动切换意愿默认开启；升级和重启仍保留原偏好。开启开关不代表已获得系统控制权限，执行仍受耳机选择、系统授权和新鲜状态约束。

首次配对后进入连接引导：在手机上完成 Mac 的 BLE 系统伴生设备关联，然后在 Mac 选择耳机、手机确认同一副耳机并授权控制。可以暂时跳过，首页和设置可继续完成；安卓保存未完成状态。

扫码页面也使用 Compose，预览使用 AndroidEmbeddedExternalSurface 交给 Camera2；SurfaceTexture 已处理传感器方向，页面只补偿屏幕旋转并等比裁切，不再重复旋转画面。按钮、提示和所有应用对话框均由 Compose 渲染。后台连接、蓝牙与日志服务保留 Java 实现，没有使用 AndroidView 包装旧页面。

安装页面直接展示可点击复制的公开下载地址。Mac 保留下载二维码；Android 增加 Mac App 介绍、复制地址和打开下载页入口。

“切换后原设备仍在播放”移入帮助与诊断。Mac 可主动申请 Music / Spotify 自动化权限；Android 可打开通知使用权设置以控制媒体会话。仅在用户需要时解释并授权，不是首次引导的必需步骤。

解除配对立即清理本机授权状态，并尽力发送一次通知；不等待对方确认、不重试。Mac 使用当前已经认证的 TLS 事件等待连接发送，手机使用签名请求。未在线的对端可能保留旧配对，需要在对端手动解除。

## Mac 导航与菜单

返回与设置使用原生 NSToolbar 图标项，页面名称显示在窗口标题中。macOS 26 及以上由系统绘制 Liquid Glass，macOS 14/15 使用对应系统的普通工具栏样式；不依赖仅限 macOS 26 的玻璃 API。鼠标切换页面不强制聚焦导航按钮，键盘导航保留系统焦点提示。

应用菜单提供关于、设置、显示、隐藏和退出。菜单栏图标菜单分成四组：

1. 显示 Sound Link。
2. 耳机切换到此 Mac、自动切换、暂停／恢复设备连接。
3. 设置、导出诊断日志、关于。
4. 退出 Sound Link。

自动切换的勾选与首页一致。手动切换不要求开启自动切换，也不改变这个偏好。它复用现有蓝牙连接、默认媒体输出验证和声音恢复执行器，最多验证 5 秒。目标变化、退出、睡眠或保护状态变化会取消动作；已有交接或手机独立接管时暂不可用，避免重叠执行。手动操作不补发旧手机播放器暂停；完成后重建自动播放基线。

## 外观与全屏布局

两端“通用”分组提供跟随系统、浅色、深色三种外观，默认跟随系统；选择即时生效并在重启后保留。Mac 浅色使用浅灰页面、白色卡片和细灰边线；深色保留独立卡片层次。应用外观不修改系统偏好。

Android 页面铺满整个窗口，状态栏与导航栏透明，图标随应用外观选择保持对比。滚动视口延伸到导航栏下方；底部安全间距放在滚动内容内，让最后一个操作仍能停在导航栏上方。设置页提供“关于 Sound Link”，展示版本和简介。扫码页使用适合相机的深色系统栏。

## 语言

默认跟随系统，支持简体中文和英文，其他语言回退到英文。两端设置可选择跟随系统、中文或 English。

Mac 使用集中式 `Language.swift` 选择与双语文案绑定；Android 使用默认英文、`values-zh` 资源和系统 `LocaleManager`。产品页、菜单、配对引导、扫码、更新、导出入口及系统权限说明已本地化。原始诊断与来自远端的证据保留来源语言，避免翻译改变排障信息。

## 日志

- 后台采集、队列、轮转和手机摘要上报保持原有机制，与页面是否可见无关。
- Mac 导出只包含当前与上一份 JSONL 及版本／系统清单，不收集配对存储、偏好、Keychain 或整个 Application Support 目录。
- Mac 的手机数据是摘要，完整手机日志由 Android 导出。
- Android 沿用只读 ContentProvider 和临时 URI 读取授权，交给系统分享。
- 目前没有自动上传服务。日志只在用户选择导出／分享时交给指定位置或应用。

## 验证边界

构建与回归记录见 [验证记录](validation.md)。界面、日志导出与打包通过不等于耳机实际接管、ROM 锁屏恢复和 macOS 权限弹窗已完成实机验收。

### 0.6.5 设置行与弹窗

- Mac 设置分组统一 24pt 间距、标题与卡片 8pt 间距；卡片上下 8pt、左右 24pt，行高至少 44pt。入口文字显式使用 labelColor，与通用组一致，仅真正禁用的控件使用 disabled 色；相邻行之间加浅分隔线。
- Android 使用同一中性灰背景、白／深灰卡片、正文色和蓝色强调。设置组采用固定图标列、统一行内距、浅分隔线和尾部导航标记；外观值与标题同行显示。
- App 内弹窗使用统一圆角中性面板，选项左对齐并显示当前选择，内容可滚动；取消为中性描边按钮，确认为实心按钮，解除配对确认为红色。系统权限和蓝牙关联弹窗仍由 Android 系统呈现。

### 双向耳机选择（0.6.5）

Mac 与 Android 均可从本机已配对蓝牙音频设备发起选择，不要求先在 Mac 操作。对端精确匹配蓝牙地址且没有旧选择冲突时自动设置；找不到设备或会替换之前选择时，显示确认弹窗。未匹配时可以手工确认对应设备，或先在系统蓝牙配对后再选择。名称只用于展示，不用于自动识别。确认期间暂停自动切换，系统耳机控制授权仍单独保留。

手机设置、耳机页和初始引导直接订阅后台偏好变化；事件通知与心跳更新同一份按版本单调保存的状态。停留在页面即可看到另一端的选择与允许控制按钮变化。被后续选择替代的旧确认弹窗自动关闭。

### 手机名称（0.6.7）

Mac 的已配对手机卡片优先显示已授权读取的蓝牙名称；蓝牙名称不可读或为空时，回退为 Android 系统设备名称，最终回退为 Android，不使用硬件型号代码。名称通过已认证心跳更新，已有配对无需重新扫码；改变名称不改变设备身份、密钥、配对或耳机设置。

### 未配对首页（0.6.8）

两端采用一致的两块卡片：上方连接示意与“一副耳机，连接两端”，下方为图标、短标题和一句说明。Multipoint 文案明确由两端 App 协调切换，不宣称同时播放或新增耳机固件能力；AirPods 文案说明 Mac 与 Android 跨系统使用。功能介绍只显示在未配对状态，配对后保留原连接状态首页。中英文和深浅色均沿用现有语义颜色。

### 0.6.9 配对前安装引导

两端亮点强调让没有 Multipoint 的蓝牙耳机也能在 Mac 与 Android 之间流转。平台标题为 AirPods × Android × Mac；Windows 尚未实现，不纳入支持文案。Mac 首页说明先安装手机 App；配对页按「安装 APK → 在 Sound Link 中扫描配对码」分两步，下载页说明可用手机相机扫码下载安装，并提供「已安装，去配对」入口。下载页返回按钮回到实际来源页。

### Mac 0.6.10 首页内扫码

未配对首页以「安装 Android App」为主按钮，「已安装，去配对」为次按钮。点击后在欢迎卡片按钮下方展开对应二维码，下载与配对互斥显示，停留首页。下载区注明手机相机扫码，配对区注明在 Sound Link 中点击扫描配对码；上方按钮可随时切换到配对码。配对码沿用自动刷新和手动刷新，配对成功后收起。设置中的独立页面仍可使用。

### Mac 0.6.11 二维码分段选择

首页两个入口使用原生单选 segmented control，选中项为蓝色主色调。默认选中安装并显示下载码；切换至「已安装，去配对」时同步选中态与配对码。移除原安装按钮的默认 Return 操作，避免切换后仍将安装视为主操作。

### 0.6.12 连续初始设置与耳机页

初始设置按蓝牙自动重连、选择并同步耳机、允许手机控制耳机推进。进入引导即显示当前未完成步骤的 dialog；伴生关联、目标同步或耳机授权成功后自动关闭旧步骤并展示下一步。对端尚未确认时显示等待；本端需确认时复用带 revision 校验的确认流程。取消当前弹窗不会被每秒刷新重新打开，可点击继续设置恢复。已有设置会跳过完成步骤，全部就绪后展示完成弹窗。

两端耳机页统一为当前耳机（设备名称与选择／更换按钮）、跨设备同步（独立状态及 Mac／Android 各自名称）、耳机控制三个区域。已选中时按钮只写更换耳机；首页未选状态写尚未选择，不使用看起来像操作的标题。选择器在独立 dialog 内展示已配对耳机，手机通过单选标记显示当前项。Mac 清除选择放在次要位置并确认。

### 0.6.13 重置连接

两端设置「帮助与关于」的第一项为「重置连接」，始终可用，包括未配对或留下中断配对时。确认弹窗说明会清除 Sound Link 的设备配对、耳机选择及连接状态，并尝试通知对方解除配对；取消不做修改。Android 同时移除本 App 的所有伴生授权（Mac、耳机及历史残留），不解除系统蓝牙配对。语言、外观、本机身份和日志保留。清理失败时提示重试，重置可重复执行。

### Mac 0.6.14 首页直接配对

未配对首页移除安装／配对分段控件，默认只展示配对二维码。码下提示使用 Android 手机上的 Sound Link App 扫码，旁边提供下载页入口；下载二维码和复制地址放在二级页面。下载页返回及「已安装，去配对」回到原首页配对码。保留配对码自动刷新，倒计时与手动刷新放在同一行。

### 0.6.15 初始设置分端交互

Mac 初始设置使用三个状态卡片：蓝牙自动重连（手机操作与广播名称）、耳机选择/同步（内嵌选择器、确认按钮和双方名称）、手机耳机控制（授权状态与指引）。步骤完成后直接更新卡片，全部完成显示完成入口，不自动弹出 dialog；初始设置中的手机耳机提案也在卡片内确认。选择提交保留配对身份、目标 revision 和实时设备列表校验。独立耳机设置页仍保留手动打开的选择弹窗。

Android 仍使用逐步 dialog。操作区按当前语言、字体大小和可用宽度测量：取消按钮按内容占宽，主操作使用剩余宽度；横向放不下则切换为整行上下排列，不使用缩小字号或截断文字。

### Mac 0.6.16 设置完成自动返回

初始设置的蓝牙自动重连、耳机同步和手机控制均完成，且手机在线时，自动回到首页，不再需要点击完成。跳转前重新校验当前页面、配对身份、耳机版本和最新完成状态，避免旧刷新带来错误导航。未完成时仍可选择稍后设置。
